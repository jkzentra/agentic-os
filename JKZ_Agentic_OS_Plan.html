02
ECC agentic-os pattern

Five layers

The ECC skill gives four layers (kernel, agents, commands, scripts) plus state. JKZ adds one thing on top: GHL is the body that runs in real time, so the scheduler only has to handle the brain's periodic work.

Two clocks

GHL is always on (lead capture, bots, sequences). Claude runs on a schedule (briefs, drafts, ranking, QA). Neither waits for the other.

Declarative routing

Routing lives in a markdown table, not code. Boss can read it, edit it and see why a request went where it did.

Reflection every session

Each session ends with what worked, what failed, what to change. The OS improves without rewriting code.

04
Boss stays the head chef

Approval gates

Boss's only two recurring actions: approve or reject a drafted option, or supply an input only he can. Anything that makes him operate a tool is a design gap.

L0 · AUTO

Runs alone

Lead tagging, pipeline stage moves, FAQ auto-replies, daily brief compile, wrap-up files, QA checks.

L1 · DRAFT

Sends after a window

Social posts (default send), follow-ups (default hold), engagement replies. Boss can veto, or edit and his edit wins.

L2 · PROPOSE

Never sends unapproved

Quotes, proposals, contracts, high-value first touch, ad budgets, any credit spend. Needs an explicit "Approved". No timeout, ever.

L3 · HUMAN ONLY

Boss does it

Pricing strategy, refunds, scope changes, legal commitments, credentials, compliance sign-off.

07
Nothing lost between sessions

Memory and state

No database. Knowledge lives in the vault. Machine state lives in plain files. Contacts and the approval queue live in GHL, so nothing is duplicated.

│  └─ 04_Reference\pain-library\  # industry-level pains, no client names
└─ every note: tags · status · last-updated · linked

Memory scope per agent

Each agent file lists exactly what it may read and append. @offer reads the catalog and brand rules. It cannot read PhoneLab data. Separate stacks stay separate.

Append-only logs

Past daily logs are never edited. Decisions go in as short records: what, why, who approved, what it supersedes. Every document carries a Doc Meta block.

Secrets never in files

Tokens and logins live in environment variables or a gitignored .env. A token pasted in chat gets rotated, no exceptions.
